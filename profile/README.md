# PhoenixUSBPro - The Allwinner Tool a Newer Image May Require

## At a Glance

Allwinner's flash tools overlap. An image that opens in PhoenixUSBPro may refuse LiveSuit, and the reverse is also true. Read the release note that came with the file. If it says PhoenixUSBPro, install that, install its driver, and ignore the older icon that still sits on the bench PC.

- The image and the tool are a pair
- FEL or the USB mode this build shows
- One product image, not a chipset-only pack
- Verify or a full write you can watch
- The last good image kept until this one boots

A black screen after a "successful" burn is often the wrong panel or the wrong RAM size, not a cable that needs a third tool. Go back to the file for this PCB.

## Steps

1. Install PhoenixUSBPro and its driver. Remove confusion by not starting two Allwinner tools at once.
2. Enter the mode the guide uses and confirm a device is listed.
3. Load this board's image.
4. Start the burn and leave the port alone.
5. Boot and check display, storage, and network.
6. If those are wrong, burn the previous known-good image.

## Fits

Allwinner boards whose vendor specifically shipped PhoenixUSBPro. A poor fit when the manual still says LiveSuit and the file opens there. A poor fit for other chipset families. A poor fit for file recovery from a unit that still starts.

## Fixes

The image will not load. Try the tool the vendor named, not every suit on the disk.
No device. Driver or button combo.
Two tools fight for the port. Close the other one.
Wrong firmware features. Wrong SKU. Reflash the right file.
You burned a working board to test a file. Only the previous image undoes it.

## One Suit, One Image

PhoenixUSBPro exists so a newer Allwinner package is not forced through LiveSuit. If the image will not open, you are in the wrong generation of the tool, not a bad USB port. Install this program and its driver, close every other Allwinner flasher, and only then enter the USB mode the guide names. Two tools on one port produce a device that appears and vanishes.

Burn the file for this PCB. A shared SoC does not mean a shared panel or a shared RAM size. Keep the previous image until the new one shows a picture and the network you expected. A unit that still boots should be copied off before a test flash. The bar completing is not a request to delete the last known-good file.

- Vendor note read for the tool name
- Other suits closed
- Device listed before the image is started
- SKU matched, not only the chip
- Previous image kept
- Same file retried once if the device drops
- Working boards not erased to test a download

| Result | Response |
|---|---|
| Image will not load | Switch to the tool the vendor named |
| No device | Mode or driver |
| Boots with the wrong screen | Burn the SKU file |
| Success | Boot once before you archive the old image |

The folder name is the safety check. PhoenixUSBPro will write the next file you click.

## Boot Once Before You Delete the Old File

A finished bar is not a finished board. Wait for a picture and the network. If the panel is wrong, the image was another SKU. Burn the previous file you kept. Do not start LiveSuit at the same time. One port, one tool, one product image. A unit that still boots should be copied off before you experiment.

- Previous image retained
- Other suits closed
- SKU read from the board, not the chip
- First boot checked
- Folder labeled
